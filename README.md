# Data Quality & Root Cause Agent

A small Python tool that checks a table for data quality problems and then suggests where each problem probably comes from. It reports what it found, which rows are affected and the evidence behind each suggestion. Causes are written as hypotheses, never as facts.

## What it checks

| Check | Finds |
|---|---|
| missing | empty or blank values in required columns |
| duplicate | repeated keys, and whether the repeats are exact copies |
| type | values that do not fit the expected type (int, float, ISO date) |
| rule | business rules, for example "amount must be positive" |

## Root-cause hypotheses

`root_cause.py` looks at the affected rows and applies simple, readable rules:

- Missing values that cluster in one source point to that source not sending the field.
- Exact duplicate rows point to a double load; repeated keys with different values point to a re-sent record.
- Placeholder text such as `N/A` or `unknown` in a number column points to a source that writes text for unknown values.
- Mixed formats point to two sources or entry screens.

Each hypothesis comes with its evidence. Optionally, `explain_with_llm()` sends only the findings (no raw rows) to a model and asks for a short plain-language explanation. That text is labelled as a suggestion to verify.

## Run

    py -m pip install pandas
    py run_demo.py

This builds a small sample orders table with known problems, runs all checks and writes `report.md` and `report.json`. It needs no API key. For the optional model explanation:

    set GEMINI_API_KEY=your_key
    set LLM_MODEL=gemini-3.5-flash-lite
    py run_demo.py --llm

If no key is set, `llm_client.py` asks for one when it starts.

## Test

    py -m unittest test_dq.py

## Limits

- The sample data is generated by me with the problems built in, so the demo shows the method, not accuracy on real data.
- The hypotheses are simple heuristics. They suggest where to look first and can be wrong.
- No real dataset, user study or measured precision yet.
